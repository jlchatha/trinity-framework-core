Common Setup Process

All agents share the same basic setup process using the provided scripts:

<h1>Navigate to the setup directory</h1> cd trinity-framework-core/tools/setup

<h1>Make scripts executable</h1> chmod +x *.sh

<h1>Create agent workspace</h1> ./setup-[agent-name].sh [workspace_path]

Replace [agent-name] with apex, analyst, or historian and [workspace_path] with your desired workspace location.

APEX Agent Setup

The APEX agent serves as the primary interface between the human operator and the Trinity system.

1. Create APEX Workspace

./setup-apex.sh ~/trinity/trinity-apex-workspace

2. Review and Customize AGENT.md

Open ~/trinity/trinity-apex-workspace/AGENT.md in your editor and modify:

    1. The introduction section to reflect your specific system purpose
    2. Decision framework criteria based on your project needs
    3. Tools and script references to match your infrastructure
    4. Interaction protocols for your organization's requirements

3. Configure User Interface Settings

APEX agents require clear user interaction guidelines:

    1. Define acceptable input formats
    2. Set up response templates
    3. Configure communication protocols
    4. Establish escalation paths

4. Implement APEX-Specific Tools

Create APEX-specific tools in the /tools directory:

mkdir -p ~/trinity/trinity-apex-workspace/tools/user-interface mkdir -p ~/trinity/trinity-apex-workspace/tools/task-management mkdir -p ~/trinity/trinity-apex-workspace/tools/status-reporting

5. APEX Verification

Verify your APEX agent setup:

./verify-installation.sh ~/trinity/trinity-apex-workspace

Optional: Context Management Integration

For each agent, you can implement the optional context management system:

1. Create Context Management Directories

<h1>For each agent workspace (replace [agent-type] with apex, analyst, or historian)</h1> cd ~/trinity/trinity-[agent-type]-workspace mkdir -p tools/token-tracker/context-manager/bin mkdir -p tools/token-tracker/context-manager/state mkdir -p tools/token-tracker/context-manager/checkpoints

2. Copy Context Management Tools

<h1>Copy context management tools from framework repository</h1> cp -r ~/trinity/trinity-framework-core/examples/context-tracking/* tools/token-tracker/ chmod +x tools/token-tracker/context-manager/bin/*.sh

3. Update Protocol Files

Update the relevant sections in each protocol file to include context tracking:

    1. AGENT.md: Uncomment the context tracking protocol section
    2. AUTO-COMPACT.md: Update the context metrics section
    3. STATUS.md: Enable the context health section

Multi-Agent Integration

When running multiple agents as part of the same system:

1. Establish Communication Channels

Define how agents will communicate with each other:

<h1>Create shared communication directory</h1> mkdir -p ~/trinity/shared chmod 777 ~/trinity/shared

<h1>Create symbolic links in each workspace</h1> ln -s ~/trinity/shared ~/trinity/trinity-apex-workspace/shared ln -s ~/trinity/shared ~/trinity/trinity-analyst-workspace/shared ln -s ~/trinity/shared ~/trinity/trinity-historian-workspace/shared

2. Configure Agent Awareness

Modify each agent's AGENT.md to include awareness of other agents:

<h2>Agent Ecosystem Awareness</h2>

You oversee the following agents:

  1. <strong>APEX</strong> (/path/to/trinity-apex-workspace/)
- User interface responsibilities - Task management

  1. <strong>ANALYST</strong> (/path/to/trinity-analyst-workspace/)
- Implementation responsibilities - System improvement

  1. <strong>HISTORIAN</strong> (/path/to/trinity-historian-workspace/)
- Documentation responsibilities - Knowledge management

3. Define Interaction Protocols

Create an AGENT-INTERACTION.md file in each workspace that defines:

    1. Communication formats
    2. Responsibility boundaries
    3. Collaboration workflows
    4. Escalation procedures

Agent Customization Guidelines

When customizing agents for specific roles:

  1. Maintain Framework Compliance: All changes must adhere to Framework 2.0 standards
  2. Preserve Protocol Files: Keep the core protocol files intact and functional
  3. Respect Directory Structure: Follow the standard workspace organization
  4. Document Customizations: Create clear documentation for custom elements
  5. Verify After Customizing: Run verification checks after customization

Best Practices

Protocol File Customization

    1. Keep the core recovery sections intact
    2. Only modify sections clearly marked for customization
    3. Document any customizations with comments
    4. Test recovery protocols after customization

Workspace Organization

    1. Keep all protocol files in workspace root
    2. Limit root directory to 10 files maximum
    3. Organize project files in the /projects directory
    4. Keep documentation in the /docs or /reports directories

Context Management

    1. Test context tracking before deploying to production
    2. Customize token estimates based on your actual usage
    3. Adjust thresholds if needed for your specific workflow
    4. Test recovery procedures regularly

Next Steps
